# Figma Codex MCP Bridge — установка

Это готовый комплект для управления Figma из основного чата Codex. Нужны Node.js 24 или новее, Figma Desktop и установленный Codex с вашим входом. Исходный код для установки не требуется.

[Краткая инструкция подключения моста](INSTALL-BRIDGE.md).

Команда `create_component_variants` создаёт согласованные варианты клонированием исходных компонентов в существующий локальный набор с layoutMode=NONE. По умолчанию работает без записи (`dryRun: true`). Применение требует того же запроса, `dryRun: false` и `expectedState` из preview. Необязательные `componentSetSize:{width,height}` и `newVariantValues:{theme:["light"]}` разрешают согласованную рамку и используемые новые значения существующих осей. Исходная геометрия и defaultValue сохраняются. При ошибке удаляются новые копии и восстанавливается записанная операцией рамка; ручные размеры не перезаписываются. Повтор использует прежний operationId и проверяет результат, включая рамку/схему. Согласуйте точные источники, свойства, координаты, стили и дополнительные параметры; прежнее разрешение на эти же изменения действует. Первая версия проверена в Figma на sort icon 24. После установки перезапустите плагин Figma и Codex/MCP: запущенные процессы новые возможности не подхватят.

## 1. Сохраните папку

Скопируйте весь комплект в постоянную папку на компьютере. После настройки Codex будет запускать мост из неё. Откройте PowerShell в этой папке и выполните:

```powershell
npm.cmd ci --omit=dev
npm.cmd run install:skills
```

Команда установки навыков копирует все навыки из `skills` в папку навыков вашего Codex. Затем перезапустите Codex, чтобы он обнаружил их. Навык `figma-bridge` задаёт правила выбора активного файла и выделенных объектов.

## 2. Подключите MCP к Codex

В той же папке выполните:

```powershell
$bridgePath = (Resolve-Path 'dist\bridge\index.js').Path
codex.cmd mcp add figma-codex-local -- node "$bridgePath"
codex.cmd mcp get figma-codex-local
```

Перезапустите Codex. Он запускает мост автоматически. Отдельно запускать `npm start` для обычной работы не требуется. Если порт `3846` занят другим сеансом, мост ждёт его освобождения; закройте лишний сеанс Codex.

## 3. Установите плагин Figma

В Figma Desktop откройте **Plugins → Development → New plugin → Figma design → Custom UI**. Сохраните шаблон в отдельную папку: Figma назначит ему ваш ID.

В PowerShell, открытом в папке комплекта, выполните, подставив путь к созданной папке:

```powershell
npm.cmd run install:figma -- "C:\Figma\my-bridge-plugin"
```

Запустите плагин через **Plugins → Development**. В чате Codex попросите: «Дай код подключения Figma». Вставьте полученный код в плагин. Следующие подключения будут автоматическими.

## Работа и обновление

Оставляйте плагин открытым в каждом файле, которым хотите управлять. Команды выполняются в активной вкладке Figma. Для указаний «эта иконка» или «этот блок» выделите нужный объект. Если активная вкладка неизвестна, Codex может попросить выбрать файл.

Для обновления сохраните новый комплект поверх этой папки, повторите `npm.cmd ci --omit=dev`, `npm.cmd run install:skills` и `npm.cmd run install:figma` с прежним путём. Затем перезапустите плагин и Codex. Личный код подключения хранится отдельно и не входит в комплект.

Для экспорта в React/Storybook мост передаёт привязки токенов, прямые и наследуемые режимы, схемы свойств компонентов и значения вариантов. Инструмент `get_variables` читает коллекции, значения всех режимов, цепочки алиасов и итоговое значение Figma для указанного узла. Проверяйте предупреждения и полноту выгрузки; точность переноса подтверждается сравнением рендера с макетом. Подробности — в [навыке figma-bridge](skills/figma-bridge/SKILL.md) и [контракте переменных](skills/figma-bridge/references/variables.md).

`assets/plugin-icon.png` — изображение для публикации. У локального dev-плагина в меню и верхней полосе окна используется системный значок Figma.

`bundle-info.json` содержит дату сборки и контрольные суммы файлов. Комплект генерируется из проекта; изменения в этой папке не возвращаются в исходный код.
