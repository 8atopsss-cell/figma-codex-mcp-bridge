## 1. Подтверждённый пример

Живое подключение: файл `SD Enterprice`, страница `UI kit` (`933:24166`), выделенный COMPONENT_SET `1599:48606`, имя `icon 24/sort icon  dp`.

- `theme`: VARIANT, default `dark`, options `dark`, `light`.
- `state`: VARIANT, default `ascending`, options `ascending`, `descending`, `none`.

| ID | theme | state | x/y внутри набора |
|---|---|---|---|
| `661:33189` | dark | ascending | 20 / 20 |
| `1599:48607` | dark | descending | 20 / 64 |
| `1599:48611` | dark | none | 20 / 108 |
| `15512:103567` | light | ascending | 75 / 20 |

Все компоненты 24×24. В каждом три VECTOR: strokeWeight 2, strokeAlign CENTER, strokeCap ROUND, fills пуст. В прочитанных узлах boundVariables, explicitVariableModes и resolvedVariableModes пусты. Связи цвета заданы **PaintStyle**, а не переменными; одинаковый RGB не является основанием для назначения стиля.

Набор: 119×196, layoutMode NONE, clipsContent true. Предлагаемые новые координаты: light descending `(75, 64)`, light none `(75, 108)`. Новые рамки до x=99/y=132 помещаются в существующие размеры. Это предлагаемые координаты размещения, не полученные свойства отсутствующих компонентов.

## 2. Причина ограничения и варианты решения

Текущее состояние исходников:

- `src/shared/protocol.ts`: создание только page/screen, node.update и node.delete; screen допускает frame/text/rectangle.
- `src/plugin/write.ts`: COMPONENT/COMPONENT_SET допускают только patch.name. VECTOR не поддерживается. Нет clone, append в набор, назначения PaintStyle.
- `src/plugin/main.ts`: отсутствует обработчик создания вариантов.
- `src/bridge/mcp.ts`: отсутствует соответствующий инструмент; очередь записи существует, фиксация текущего подключения используется сейчас при удалении.
- Manifest содержит documentAccess=dynamic-page: для назначения стилей нужны асинхронные методы Figma.

Возможные подходы:

1. **Рекомендуемый:** отдельная команда клонирования вариантов с заменой стилей только на новых слоях. Сохраняет источник и ограничивает область изменений.
2. Общие команды duplicate/reparent/update для любых узлов. Гибче, но требуют нескольких записей; между ними возможны дубли и незавершённые варианты. Для текущей задачи избыточно.
3. Создание компонентов с нуля из JSON/SVG. Потребует восстановления свойств и связей, хотя полноценный исходный компонент уже существует.

Использовать `ComponentNode.clone()` и `ComponentSetNode.appendChild()`. Набор не пересоздавать через combineAsVariants; его существующий ID и ID четырёх компонентов сохранить. `variantProperties` readonly: задать каноническое имя нового компонента и после добавления прочитать реальную схему/сочетание. Не назначать variantProperties напрямую.

Официальные источники:

- https://developers.figma.com/docs/plugins/api/ComponentNode/ — clone, variantProperties, методы назначения стилей.
- https://developers.figma.com/docs/plugins/api/ComponentSetNode/ — добавление детей в существующий набор.

## 3. Контракт первой версии

Название инструмента: `create_component_variants`. Протокольный метод: `component.variants.create`.

Пример запроса для выбранного набора:

```json
{
  "componentSetId": "1599:48606",
  "operationId": "sort-light-2026-10-05-v1",
  "dryRun": true,
  "variants": [
    {
      "sourceComponentId": "1599:48607",
      "properties": { "theme": "light", "state": "descending" },
      "position": { "x": 75, "y": 64 },
      "layerStyles": [
        { "sourceNodeId": "1599:48608", "strokeStyleId": "S:876da3bca148d8c8dbf5e060015b09c5a6b9fd9d," },
        { "sourceNodeId": "1599:48609", "strokeStyleId": "S:876da3bca148d8c8dbf5e060015b09c5a6b9fd9d," },
        { "sourceNodeId": "1599:48610", "strokeStyleId": "S:876da3bca148d8c8dbf5e060015b09c5a6b9fd9d," }
      ]
    },
    {
      "sourceComponentId": "1599:48611",
      "properties": { "theme": "light", "state": "none" },
      "position": { "x": 75, "y": 108 },
      "layerStyles": [
        { "sourceNodeId": "1599:48612", "strokeStyleId": "S:630b4a901d4183a475990a76255a82de9f27475f," },
        { "sourceNodeId": "1599:48613", "strokeStyleId": "S:630b4a901d4183a475990a76255a82de9f27475f," },
        { "sourceNodeId": "1599:48614", "strokeStyleId": "S:630b4a901d4183a475990a76255a82de9f27475f," }
      ]
    }
  ]
}
```

Правила контракта:

- Zod strict на всех объектах. От 1 до 20 вариантов; до 200 переопределений слоёв на вариант; до 20 variant-свойств. Позиции конечные, диапазон −100000…100000. Пустые имена/ID и повторные sourceNodeId в одном варианте запрещены.
- `dryRun` по умолчанию true. Результат: status=preview, operationId, componentSetId, канонические имена, источники, перечень изменений стилей, координаты, `expectedState`.
- `expectedState` — непрозрачная строка стабильного JSON-снимка подготовленных источников, набора и используемых PaintStyle. Не криптографическая подпись и не согласие пользователя. Снимок должен включать схему, состав и порядок детей, локальные свойства/геометрию источников, vectorPaths/vectorNetwork, ссылки свойств, стили и bindings/modes. Исключать ID будущих копий и абсолютные координаты, не определяющие локальную геометрию. Канонически сортировать ключи объектов, сохранять порядок массивов. При getter-ошибке отказаться от подготовки, не подставлять пустое значение.
- Ограничить обход одним источником до 2000 узлов/16 уровней; expectedState до 256 KiB UTF-8. При превышении вернуть LIMIT_EXCEEDED до записи. Существующий транспорт ограничен 4 MiB; не передавать preview PNG в этом ответе.
- Для записи передать тот же запрос с dryRun=false и expectedState из preview. Перечитать подготовленное состояние; при расхождении вернуть SOURCE_CHANGED до clone. Значение expectedState должно соответствовать именно этому запросу, включая назначения стилей и позиции.
- properties должен содержать все и только VARIANT-ключи текущей схемы. Первая версия допускает только значения, уже имеющиеся в variantOptions; создание новых осей и значений отдельно не входит в задачу.
- При генерации имени соблюдать порядок VARIANT-ключей схемы. Запретить `,` и `=` в ключах/значениях, если не реализовано документированное экранирование, чтобы имя не создало другое сочетание.
- layerStyles содержит fillStyleId и/или strokeStyleId непустого существующего PAINT-стиля. В выбранном примере нужны только strokes. Слой определяется исходным ID внутри указанного компонента; имена Vector не использовать как уникальный ключ.
- Сначала поддержать локальный существующий набор с layoutMode=NONE и локальные исходные компоненты непосредственно из этого набора. Новые рамки должны помещаться внутри его размеров без пересечений с существующими/другими новыми рамками. Auto Layout, изменение размера набора, перенос из другого набора, импорт библиотек, новые variable bindings и переключение режимов — отдельные расширения.
- Не менять стиль по совпадению RGB. На неуказанных слоях сохранять клонированные связи; на переопределяемом канале назначать целевой PaintStyle и его реальные bindings. Проверять setters и прочитанные обратно связи; не обещать сохранение заменённого исходного binding.

Значимые сценарии новых тестов:

2. Дубликаты существующих/запрошенных сочетаний отклоняются до clone.

8. Переключение активного файла после постановки в очередь не меняет целевое подключение; две записи не пересекаются.
9. Фактический plugin message handler принимает новый метод, сохраняет ошибки и возвращает структуру результата. Старые чтения/записи продолжают работать.
