## Необходимое расширение текущего MCP

Подтверждено чтением схемы инструмента и исходников:

- update_node для COMPONENT_SET допускает только name.
- create_component_variants не меняет размеры набора и отклоняет выход новых рамок за его границы.
- create_component_variants разрешает только значения, уже имеющиеся в variantOptions. После переименования существующих трёх компонентов theme будет иметь только dark; light отсутствует.

Первоначальная задача sort24 не требовала этих возможностей, поскольку light уже существовал и размеры позволяли добавить две копии.

Расширить create_component_variants явными необязательными параметрами `componentSetSize: {width,height}` и `newVariantValues: {theme:["light"]}`. По умолчанию ограничения прежние. Эти параметры входят в dryRun, expectedState, нормализованный запрос для повторов, перечень согласуемых изменений и ответ.

Не создавать новые оси произвольным запросом: theme/state появляются от согласованного переименования трёх существующих вариантов. Новое значение light возникает при добавлении новых компонентов с этими именами. Проверять фактическую схему после вставки.

Подготовка должна учитывать предложенную рамку. Контроль неизменности после записи допускает только согласованные размеры и добавление перечисленных значений; остальные свойства и defaultValue сохраняются. При ошибке удалить новые копии и восстановить исходные размеры, если они всё ещё соответствуют записанным этой операцией; ручные изменения пользователя не перезаписывать. О неудаче восстановления рамки сообщать с ID набора и фактическими размерами. Повтор проверяет и созданные варианты, и согласованную рамку/схему.
