Перестановка операций не снимает запрет. Не оставлять orphan BOOLEAN и не выдавать painted clone за переиспользование.

## Предлагаемая структура

```text
header
└─ HeaderContent FRAME, vertical
   ├─ Optional label TEXT, BOOLEAN visible
   └─ Title SLOT
      └─ Title TEXT / заменяемое содержимое заголовка
```

Optional label находится вне SLOT. Title остаётся заменяемым. Body content SLOT и button bar BOOLEAN остаются отдельными областями. Палитра/тень и существующие светлые кнопки сохраняются. content_1 не возвращается.

Предполагаемые изменения (требуют уточнения миграцией):

- Dark: сохранить COMPONENT2046:48406, header2418:60886, SLOT2046:48403 и TEXT2046:48405. Новый вертикальный FRAME объединит Optional TEXT2046:48404 и прежний Title SLOT; Optional перемещается из SLOT в этот FRAME. Схема Title меняет семантику: Optional больше не входит в заменяемое содержимое.
- Light: сохранить COMPONENT4745:44256 и FRAME4745:44237 как вертикальный HeaderContent. Optional TEXT4745:44238 остаётся обычным дочерним TEXT. Новый FRAME вокруг Title TEXT4745:44239 станет Title SLOT. Светлые main components не заменяются.
- Default-вид должен сохранить позиции Optional/Title и габариты header; точные новые node IDs/геометрия/привязки будут сформированы в отдельном reviewable diff перед применением. Это предложение, не готовая команда записи.

## Влияние и обязательная миграция

Read-only inventory: 65 dark и7 light экземпляров прочитаны; Title найден в каждом, пустых не обнаружено. У45 dark значение Optional label=false. У39 dark Title children имеют недефолтные native IDs; это кандидаты на отдельную миграцию, не автоматическое доказательство пользовательской замены каждого слоя. Есть заголовки с3текстовыми слоями. Нельзя переносить детей по порядку или угадывать Optional по имени/первому TEXT.

До разрешения на запись:

1. Для каждого кандидата прочитать полное Title-содержимое, paints/bindings/overrides/видимость и actual main links; отделить унаследованный Optional по lineage/схеме от заменённого содержимого. Неоднозначные случаи остановить и показать отдельно.
2. Подготовить точную карту старых slot children и BOOLEAN значений в новую структуру. Сохранить пользовательские заголовки, дополнительные строки, скрытые labels и геометрию каждого экземпляра. Для custom Title, заменившего весь прежний SLOT, отдельно согласовать семантику нового внешнего Optional, чтобы он не появился повторно.
3. Проверить доступность reparent/новых привязок на одобренной тестовой структуре; не предполагать, что UI и API разрешают одинаковые операции. Доказать ограничения до library writes.
4. Представить точные изменения обоих master и всех затронутых экземпляров, включая новые FRAME/SLOT, изменения семантики Title, карту миграции и нерешённые случаи. Получить отдельное подтверждение этого расширенного scope.
5. Добавить явный preflight unsupported slot-sublayer BOOLEAN/TEXT refs, чтобы исходный несовместимый вариант блокировался до записи. Закрытие/разрешение прежней incomplete-операции проектировать отдельно с сохранением её истории и пользовательским решением; не обходить её новым ID.
6. Только после проверки/согласования — ограниченная миграция с readback/propertyMap/instance audit/PNG. Общий перевод окна в светлую тему проверяется отдельно после совместимости master.
