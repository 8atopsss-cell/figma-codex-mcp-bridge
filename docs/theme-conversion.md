# Перевод макета через компоненты темы

## Текущий этап

Каталог `list_components` и анализатор `plan_theme_conversion` только читают Figma. Они не создают копии, не заменяют main component, не изменяют свойства, слоты, библиотеку или метаданные. План всегда содержит `executable:false`.

Отдельный `copy_theme_component` реализует поэтапную замену одного родительского INSTANCE на новой копии через preview/apply. Это не полный рекурсивный перевод макета. После замены нужно проверить полученное дерево и перепланировать вложенные компоненты; применение вложенных тематических замен внутри INSTANCE этим инструментом пока не поддерживается. Автоматическое создание отсутствующих элементов, оркестрация FRAME и полный рекурсивный перевод остаются в [плане доработки](superpowers/plans/2026-10-28-theme-component-reuse.md). `status:review` анализатора не означает готовность к применению: совместимость схем не доказывает сохранность текста, overrides и содержимого после замены.

## Порядок работы

1. Прочитать `list_connected_files`, затем `get_file_overview`. Проверить активный файл и выбранный FRAME/INSTANCE. Получить исходное дерево, main components, их схемы и превью.
2. Найти библиотечные master-компоненты через `list_components` в явно заданных областях. Совпадение имени даёт кандидата; окончательное соответствие задаётся ID компонентов/наборов или проверенной осью темы внутри одного набора.
3. Вызвать `plan_theme_conversion`, указав исходный узел, области библиотеки и известные карты соответствий. Сохранить полные ID свойств с суффиксами `#...`; разницу значений вариантов задавать явно.
4. Рассмотреть родительский компонент первым. При несовместимых слотах сообщить **«Светлый и тёмный компоненты необходимо привести в соответствие»**, показать различия и приостановить перенос этого компонента. Не создавать обходной дубль и не подменять его фреймом.
5. Вложенные шаги предварительные (`provisional:true`, `requiresReplanAfterParent:true`). После фактической замены родителя нужно повторно прочитать его дерево и построить карту новых ID. `blockedBy` перечисляет конфликтных родителей; готовые вложенные кнопки сами по себе не снимают конфликт Modal.
6. Показать пользователю источники и целевые master IDs, карты свойств/значений, сохраняемый текст/содержимое, предложения создания и конфликты. Исправления готовой библиотеки требуют отдельного согласования. Прежнее разрешение на перекраску не разрешает замену master-компонентов или ремонт слотов.

## Каталог компонентов

```json
{ "rootNodeId": "4745:42929", "offset": 0, "limit": 50 }
```

`rootNodeId` — существующая локальная PAGE, SECTION, FRAME, COMPONENT или COMPONENT_SET. Экземпляры и их внутренние слои не считаются библиотечными master-компонентами. Перед обходом нужная страница загружается без переключения текущей страницы редактора. Поддерживаются `query`, `scanLimit` (1–20000, по умолчанию 20000), `offset` и `limit` (1–100, по умолчанию 50).

Результат: `components`, `total`, `nextOffset`, `scopeRootIds`, `scopeComplete:true`, `scannedNodes`, `scopeSnapshot`. Компонент содержит ID/key, имя, schema owner, свойства, значения варианта и состояние чтения схемы. Недоступная схема остаётся в каталоге с `schemaStatus:unavailable` и исходной ошибкой.

На следующей странице передавать `expectedScopeSnapshot` из предыдущего ответа. Изменение каталога даёт `SOURCE_CHANGED`, а не смещённую страницу из другой версии. Полная область сначала сканируется, затем пагинируется. Превышение лимита/глубины возвращает ошибку без частичного списка. Предел глубины каталога — 64, snapshot — 256 KiB, ответ — 512 KiB. При превышении сузить корни до нужных семейств.

`scopeComplete:true` относится только к указанным локальным корням. Это не доказательство отсутствия компонента на других страницах, в удалённой библиотеке или в недоступной области. Команды не импортируют библиотеки.

## Карта перевода

Пример использует ранее наблюдавшиеся ID. Перед применением примера проверить их в активном файле:

```json
{
  "nodeId": "16112:22878",
  "libraryRootIds": ["4745:42929", "4391:92031", "4553:39476", "5025:42279"],
  "targetTheme": "light",
  "mappings": [
    { "sourceId": "2046:48406", "targetId": "4745:44256" },
    {
      "sourceId": "1900:44830",
      "targetId": "4391:92045",
      "valueMap": { "size": { "32px": "32", "40px": "40" } }
    }
  ]
}
```

`sourceId`/`targetId` — ID master-компонента или набора. Точное соответствие исходного варианта имеет приоритет перед картой его набора. Для целевого набора подбирается точное сочетание состояния, размера и остальных осей; состояние disabled нельзя заменять enabled ради доступного варианта. Ось `themeProperty` по умолчанию называется `theme`, тема — `light` (также поддерживается `dark`). Существующая ось темы внутри одного набора даёт основание `same_set_theme_axis`.

`propertyMap` сопоставляет полные исходные и целевые ID свойств. Например, `{"Title#old":"Title#new"}`. Одинаковый текст до `#` — лишь подсказка. Чужие ID, несовпадающие типы и отображение нескольких исходных свойств в одно целевое блокируют шаг. `valueMap` меняет значения VARIANT-свойств явно; незнакомое значение не создаётся автоматически.

`sharedComponentIds` объявляет проверенные общие компоненты/наборы. Оно не позволяет обойти найденный тематический компонент или конфликт схем. `frameFallbackNodeIds` предлагает фрейм только для узлов без найденного соответствия; несовместимый существующий светлый компонент остаётся конфликтом.

## Результат анализатора

- `alignment_required`: отсутствующий/неверного типа/неприкреплённый слот, неоднозначная привязка, ограничения количества или недопустимое содержимое. Сообщение о приведении компонентов в соответствие; исходные/целевые свойства, затронутые узлы и требуемое исправление — в `issues`.
- `mapping_required`: неоднозначные кандидаты, разные ID свойств, непроверенные названия или значения вариантов. Сначала уточнить карту.
- `reuse`: найден точный целевой master/variant и проверены схемы. Всё ещё нужен отдельный контроль переноса данных и одобрение операции записи.
- `keep`: подтверждённый общий компонент либо экземпляр уже нужной темы внутри тематического набора.
- `missing_variant`: нет точного сочетания в существующем наборе. `proposedProperties` — предложение, не команда создания; новые оси/значения не добавляются автоматически.
- `missing_component`: соответствие не найдено в сканированной области. `absenceConfirmed:false`; `suggestedAction` предлагает вариант, отдельный компонент или явно выбранный фрейм. Сначала проверить область поиска и доступность библиотек.
- `unknown`: недоступный main/target/schema или ошибка чтения. Не заменять предположением о необходимости создать новый компонент.

Для каждого шага возвращаются source/main/schema-owner ID, target ID, основание `explicit_mapping`, `same_set_theme_axis` либо `name_candidate`, сохраняемые свойства, тексты, содержимое слотов и overrides. Результат содержит исходный и библиотечный snapshots для диагностики; это не токены разрешения на применение. Исходный экземпляр анализируется по реальному main component, а не по его имени или внешнему цвету.

Слоты проверяются и при пустом содержимом: отсутствие соответствующего слота всё равно требует согласования. Проверяются реальные привязки, типы, min/max и `allowPreferredValuesOnly` с ключами компонентов/наборов.

Ограничения содержимого проверяются ещё до предложения создать недостающий вариант; неизвестная привязка слота не отменяет проверку min/max или preferred values. Локальный master, который остался доступным по ID после удаления, не считается подходящей целью. Перед возвратом результата повторно сверяются каталог, схемы исходных/целевых masters и привязки целевых слотов. Изменение этих данных во время анализа возвращает `SOURCE_CHANGED`.

## Применение одной замены родителя

`copy_theme_component` работает с отдельным INSTANCE под PAGE или свободным FRAME (`layoutMode:NONE`), вне готовых компонентов и их экземпляров. Исходный узел и библиотечные masters не меняются. Результат — новая копия с заменённым main component. Готовый макет не заменяется автоматически.

1. Вызвать анализатор. У родителя должен быть совместимый точный целевой master (`reuse`); конфликт `alignment_required`, неизвестная схема или неподтверждённая карта блокирует запись до клонирования.
2. Прочитать полные исходные и целевые деревья. Заполнить `layerMap`: ключ — ID исходного дочернего слоя, значение — точный ID соответствующего слоя в целевом master. Нужны все слои родительской структуры; внутренняя структура вложенного INSTANCE и свободное содержимое SLOT проверяются как целые поддеревья. Названия и позиции детей не считаются доказательством соответствия. Карта слоёв отличается от `propertyMap`, где используются полные ID свойств. Отображение SLOT-слоёв обязано соответствовать карте SLOT-свойств.
3. Подготовить запрос с полями анализатора (кроме `frameFallbackNodeIds`), `operationId`, `name`, `position`, `layerMap`. По умолчанию `dryRun:true`: проверка без клонирования и записи метаданных. `expectedState` фиксирует исходник, целевой компонент и окружение, а не разрешение пользователя.
4. Показать точные ID, выбранный main component, имя/координаты копии, отображения свойств/слоёв, сохраняемые данные, ограничения и предварительные вложенные шаги. Получить согласование именно этих изменений.
5. Передать тот же запрос с `dryRun:false` и полученным `expectedState`. При изменении исходника/цели/окружения — `SOURCE_CHANGED`; заново прочитать данные и подготовить preview.
6. Проверить main component новой копии, текст, свойства, слоты, порядок содержимого, размеры и превью. Результат замены родителя не подтверждает светлую тему всех вложенных элементов. Использовать новые ID из фактического дерева; прежние вложенные шаги остаются предварительными.

Пример формы запроса; ID условные, не для отправки в живой файл:

```json
{
  "nodeId": "source-instance-id",
  "libraryRootIds": ["light-library-root-id"],
  "mappings": [{"sourceId": "dark-master-id", "targetId": "light-master-id"}],
  "layerMap": {"source-label-node-id": "light-master-label-node-id"},
  "operationId": "button-light-copy-1",
  "name": "Button light",
  "position": {"x": 700, "y": 200},
  "dryRun": true
}
```

Исполнитель переносит поддержанные свойства и содержимое, затем проверяет их фактическую сохранность; эвристика `swapComponent` сама по себе доказательством не считается. Неоднозначный перенос и неподдержанные переопределения блокируются. В частности, нельзя просто сбросить все overrides ради новой темы: среди них могут быть пользовательские иконки, текст, видимость и геометрия. Слоты не передаются через `setProperties`, а клонирование SLOT отдельно не создаёт новый SLOT.

`preservationRestores` перечисляет вложенные исходные main components, которые новая копия должна сохранить (например, пользовательскую иконку). Это восстановление исходного содержимого, а не тематическая замена вложенного компонента. `freshInventory` содержит фактические ID/главные компоненты результата; `pendingDescendantSteps` остаются предварительными шагами исходного плана. При `followupRequired:true` перевод темы не завершён.

Текущая версия требует совпадающую структуру и порядок слоёв по явной карте. Лишние целевые слои, изменение иерархии и неоднозначные соответствия блокируются. Paint-, geometry- и text-style overrides не сбрасываются и пока блокируют исполнение; отличие форматирования/привязок/реакций после переноса также приводит к откату. Сложные вложенные SLOT-композиции внутри сохраняемых поддеревьев и смешанные диапазоны целевого цвета текста пока не поддерживаются. Допустимые типы: INSTANCE, SLOT, TEXT, FRAME, GROUP, RECTANGLE, VECTOR, ELLIPSE, POLYGON, STAR, BOOLEAN_OPERATION, LINE. Неподдержанные типы (например, WIDGET) блокируются. Эти ограничения не означают, что библиотечный компонент отсутствует или требует замены фреймом.

После timeout повторять запрос с тем же `operationId`, сначала `dryRun:true`. `replayed` возвращает уже созданный результат при подтверждённой сохранности. `OPERATION_CONFLICT`, `OPERATION_RESULT_CHANGED`, `OPERATION_INCOMPLETE` и `ROLLBACK_INCOMPLETE` нельзя обходить новым ID. При незавершённом откате показать все `remainingNodeIds`, `cleanupErrors` и причину; существующие компоненты или неизвестные остатки не удалять автоматически. Откат касается только новых объектов этой операции.

Текущий Modal остаётся заблокированным: новый исполнитель не разрешает обход несовместимых слотов и не ремонтирует библиотеку.

## Отдельная операция перекраски

`duplicate_node` сохраняет прежние main components и меняет стили новой копии. Это операция внешнего вида. Она не считается переиспользованием светлых master-компонентов и не используется вместо заблокированного перевода темы.

## Установка и проверка

Сборка обновляет `dist/plugin` и transfer-пакет; локальный плагин использует корневой `manifest.json` с прежним ID. После обновления перезапустить плагин Figma и Codex/MCP, чтобы загрузились новые команды. Не создавать ещё одну папку `v_2`. Автоматические тесты проверяют каталог, карты, конфликты, preview/apply, сохранность, повторы и передачу MCP; живое применение исполнителя требует отдельно согласованной операции. Полный Modal проверяется после согласования библиотечных изменений.
