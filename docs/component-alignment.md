# Приведение схем компонентов

Типографика переносится через TextStyle и только отличающиеся записываемые поля. `openTypeFeatures` — readonly: после применения стиля их нужно сверить, а не присваивать. Равные setters тоже пропускаются, чтобы не разорвать связь текстового стиля.

Порядок применения: создать свойства → привязать SLOT → перенести перечисленные поля → привязать BOOLEAN. Структурная конверсия родителя выполняется до дочерних настроек; откат идёт в обратном порядке фактического журнала. Строгая итоговая проверка не ослабляется, неожиданные отличия выводятся ограниченной диагностикой без произвольного текста/metadata.

Для recorded incomplete-операции допускается отдельный read-only recovery preview с тем же ID и точным исходным запросом: только пустая target-схема, FRAME-кандидаты и отсутствие старых свойств/refs/values/result chunks. Preview показывает остаточное состояние, прошлую ошибку и полное влияние на экземпляры. Если все before/after изменения остаются в прежнем точно согласованном scope, повторного разрешения не требуется; расширение scope или принятие посторонних изменений согласуется отдельно. Затем применяется тот же запрос с новым recovery-prefixed expectedState, связанным с полным live snapshot и прошлым receipt. Старые failures остаются в bounded history; обычный старый apply-token не разрешает продолжение. Новым operationId и удалением receipt ошибки не обходятся. См. подробные ограничения в `skills/figma-bridge/references/component-alignment.md`.

`align_component_schema` / `component.schema.align` — отдельная ограниченная операция изменения готового локального COMPONENT. Она добавляет в существующий целевой master BOOLEAN/SLOT-свойства эталона и привязывает их к явно указанным слоям. FRAME становится SLOT через штатный `componentPropertyReferences.slotContentId`; ID, дети и основной компонент сохраняются.

## Порядок работы

1. Прочитать активный файл, source/target master, полные схемы/деревья/превью. Не брать имена или старое выделение за доказательство соответствия. Source и target — разные локальные standalone COMPONENT без владельца COMPONENT_SET; у target исходно пустая схема.
2. `bindings` задаёт полный список исходных BOOLEAN/SLOT по полным ID (`sourcePropertyId`) и точные целевые `targetNodeIds`. BOOLEAN привязывается к visible; SLOT — к существующему FRAME. Несуществующие/непривязанные свойства не копируются молча и требуют исправления источника. Вложенные main components не подменяются.
3. `fields` задаёт только явные пары `sourceNodeId`/`targetNodeId` и разрешённые поля: `paddingRight`, `width`, `layoutGrow`, `layoutAlign`, `layoutSizingHorizontal`, `textAutoResize`, `characters`, `typography`. Значения читаются из эталона, произвольного patch/JS нет. `typography` переносит поддержанные параметры текста без красок; вложенному тексту экземпляра можно передать characters, сохранив его светлый main.
4. Выполнить `dryRun:true` (по умолчанию). Preview не пишет схему/метаданные. Он фиксирует snapshots и возвращает точные изменения и `instanceImpact`: правка master распространяется на связанные экземпляры. При неподдержанном состоянии/превышении лимита остановиться; не принимать частичный анализ за полный.
5. Показать точный scope и получить согласование готового master и его затронутых слоёв. Уже выданное согласование тех же изменений действует. Preview не даёт разрешения; новый scope требует отдельного решения.
6. Применить неизменный запрос с `dryRun:false` и `expectedState` из preview. При SOURCE_CHANGED перечитать живое состояние и подготовить новый preview. Не добавлять удалённые пользователем свойства обратно.
7. Прочитать реальную схему, новые полные property IDs, refs, FRAME/SLOT-типы, IDs/keys, порядок детей, тексты, светлые стили/main components и результат на связанных экземплярах. Затем перепроверить тематическую совместимость по возвращённой `propertyMap` и посмотреть PNG-превью. Визуальное принятие — за пользователем.

## Повтор и ошибки

После timeout использовать тот же `operationId`, сначала preview. `replayed` — ранее созданная схема с проверенным сохранённым результатом. OPERATION_CONFLICT, OPERATION_RESULT_CHANGED, OPERATION_INCOMPLETE и незавершённый откат нельзя обходить новым ID. Ошибка native FRAME/SLOT-конверсии не разрешает удалять/пересоздавать контейнеры.

При частичном изменении/неполном откате показать `changedNodeIds`, `createdPropertyIds`, ошибки восстановления и причину. Не объявлять операцию атомарной: обратная FRAME/SLOT-конверсия и сохранение существующих instance overrides зависят от Figma API. Не удалять существующие узлы и не перезаписывать ручные изменения ради отката.

Перед удалением добавленного операцией свойства при откате проверяются все живые refs и значения экземпляров: если пользователь уже использовал это свойство, оно сохраняется с отчётом о незавершённом откате. Восстановление master само по себе не означает восстановление экземпляров; их содержимое и main links проверяются отдельно. После частичного применения receipt остаётся incomplete даже при восстановлении, чтобы повтор не скрывал произошедшую ошибку.

Текущие ограничения: у target должна быть пустая схема; source содержит только полную поддержанную BOOLEAN/SLOT-схему; недоступные/смешанные параметры типографики и несколько разных paint/binding-диапазонов блокируются. `autoRename:true` у изменяемого текста требует отдельного решения и блокируется до записи. Шрифты всех изменяемых TEXT загружаются перед первой правкой. Native изменения геометрии допускаются только в точных значениях эталона, показанных в preview; произвольные сдвиги и matrix coefficients не игнорируются. Добавление override `characters`/`styledTextSegments` допускается лишь для точных запрошенных TEXT IDs внутри соответствующего INSTANCE; другие overrides и пользовательские тексты сохраняются.
