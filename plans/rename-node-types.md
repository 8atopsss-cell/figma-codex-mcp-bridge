# План: переименование GROUP, VECTOR, INSTANCE и ELLIPSE

## Подтвержденная причина

В `src/plugin/write.ts:69–98` обработчик `updateNode` принимает чистый patch `{ name }` для COMPONENT и COMPONENT_SET. Затем проверка на строке 77 допускает только FRAME, TEXT и RECTANGLE. GROUP, VECTOR, INSTANCE и ELLIPSE получают `UNSUPPORTED_NODE` до присваивания имени.

`src/shared/protocol.ts:106–120` уже принимает `patch.name`; расширять схему для четырех типов не требуется. Описание `update_node` в `src/bridge/mcp.ts:172` сообщает только о COMPONENT и COMPONENT_SET. Тесты `tests/write.test.ts:23–36` покрывают их переименование и отказ при более широком patch.

Проверен локальный исходный код. Запущенная версия плагина и конкретные Figma-узлы не проверены. Заявленные количества — данные пользователя: 8 + 70 + 66 + 28 = 172 узла.

## Предлагаемый объем

Сохранить `update_node` и формат `{ nodeId, patch: { name } }`. Расширить существующую ветку чистого переименования на четыре указанных типа. Другие типы добавлять только отдельным обоснованным изменением. Новая команда и пакетный API для исправления этой ошибки не нужны.

## Этапы

1. Перед реализацией проверить Git status, ветку, remote; выполнить fetch и сравнить HEAD с upstream по `github-two-machine-sync`. Сохранить чужие изменения `AGENTS.md`. При подготовке этого плана fetch не запустился из-за ошибки среды `apply deny-read ACLs`; актуальность относительно remote не подтверждена.
2. В `src/plugin/write.ts` включить GROUP, VECTOR, INSTANCE и ELLIPSE в ветку, которая допускает исключительно поле `name` и возвращает `{ nodeId, name }`. Проверять состав patch до первой записи. Не расширять для этих типов доступ к геометрии, заливкам, тексту или layout.
3. В `src/bridge/mcp.ts` уточнить описание поддерживаемых типов и ограничения name-only. В `skills/figma-bridge/SKILL.md` добавить правило использования чистого patch при переименовании. Если обновляется установленная копия скилла, синхронизировать обе копии.
4. В `tests/write.test.ts` добавить параметризованные проверки четырех типов: успешное переименование; отказ для `name` вместе с `x`, `fill` или другим полем без частичного изменения; сохранение остальных свойств. Сохранить покрытие COMPONENT и COMPONENT_SET. Проверить `NODE_NOT_FOUND` и валидацию пустого/слишком длинного имени по существующей схеме. В MCP-тестах проверить прохождение `{ name }` до `node.update` и возврат результата/ошибки.
5. Выполнить `npm.cmd run typecheck`, `npm.cmd test`, `npm.cmd run build`. Проверить регенерированный `transfer/figma-codex-mcp-bridge`: актуальный plugin build и проектные skills; отсутствие pairing tokens, персональных manifests, настроек аккаунта и node_modules. Генерируемые файлы напрямую не редактировать.
6. Загрузить обновленный плагин и проверить в Figma по одному узлу каждого типа. Для INSTANCE отдельно проверить корневое имя и имя дочернего ELLIPSE внутри Badge: возможность записи во вложенные слои требует проверки реального API. Сравнить имена, структуру, геометрию, стили и связь с исходным компонентом до/после. Если Figma запрещает конкретный случай, отразить ограничение; не отсоединять экземпляр ради переименования.
7. Перед обработкой заявленных 172 узлов прочитать активный файл и актуальные узлы. Подготовить список `file / nodeId / type / oldName / newName`. Проверить полноту списка и новые имена. Получить явное подтверждение точных изменений готовых компонентов, экземпляров и их подслоев по правилам проекта.
8. Выполнить согласованные переименования последовательно существующей командой. При ошибке остановиться, сохранить результаты выполненных операций, перечитать проблемный узел и выяснить причину. Не заявлять атомарность всей серии. После завершения перечитать имена и выдать список успехов, отказов и необработанных узлов.

## Критерии готовности

- Четыре указанных типа принимают чистый patch `{ name }` через bridge.
- Более широкие patch для них отклоняются до изменения имени.
- Переименование не меняет другие свойства и не требует загрузки шрифтов.
- Старое поведение FRAME, TEXT, RECTANGLE, COMPONENT и COMPONENT_SET сохраняется.
- Typecheck, тесты и build проходят; transfer bundle проверен.
- Реальная проверка Figma подтверждает заявленные случаи либо фиксирует конкретные ограничения.

## Решения, оставшиеся за пользователем

Новые имена и точный список объектов пока не заданы. Переименование INSTANCE означает изменение выбранного экземпляра; изменение имени исходного компонента в этот план не входит. Подтверждение реализации bridge не заменяет подтверждение конкретных изменений готовых Figma-объектов.
