# Align existing component schemas

Use `align_component_schema` only for a separately agreed finished-master alignment. This is an in-place edit affecting target instances, not a theme-copy fallback or permission to repair every incompatible library component. Resolve active file, exact source/target IDs, full trees/schemas and previews first. Same exact prior approval remains valid; changed scope requires a new decision.

Source/target must be distinct attached local standalone COMPONENTs; target initially has an empty schema. `bindings:[{sourcePropertyId,targetNodeIds}]` explicitly covers all source BOOLEAN/SLOT properties. Copy only actual live source properties; a user-deleted property stays absent. BOOLEAN attaches to visible. SLOT attaches to an existing direct-owned FRAME through `slotContentId`, preserving IDs/children and merging other refs. No guessed name maps, orphan properties, imports, detach, main swaps or node deletion.

Apply structural SLOT bindings before descendant fields and BOOLEAN bindings: native FRAME-to-SLOT conversion can reset descendant references or sizing. After slots, apply the exact requested fields; bind BOOLEAN last. Rollback follows the reverse actual journal (BOOLEAN, fields, SLOT) and still reports any incomplete inverse. Final full preservation checks remain mandatory. Native behavior outside the planned fields is not a waiver; bounded differences must be reported without dumping arbitrary text or metadata.

`fields:[{sourceNodeId,targetNodeId,fields}]` supports only paddingRight, width, layoutGrow, layoutAlign, layoutSizingHorizontal, textAutoResize, characters and typography. Values come from the verified source; no arbitrary patch/eval. Typography excludes paints. Nested INSTANCE text can receive characters only; preserve its main component and custom content.

Native typography: apply the source TextStyle first, skip setters whose current value already equals the desired value, then verify derived readonly OpenType features. Never assign TextNode.openTypeFeatures directly. Matching setters can detach a linked text style, so copying equal values is not harmless. Unsupported readonly-feature transfer without an applicable style must stop before scene writes.

Run dryRun=true before apply. Inspect exact planned property/field changes and complete instanceImpact. Font/state/snapshot limits or unsupported preservation stop the operation. Explain that changing a master propagates to existing instances; don't claim impact is local to one visible master.

Preview expectedState is an opaque versioned SHA-256 fingerprint bound to the exact request and full canonical live snapshot. Internal complete snapshots have an 8 MiB cap; result payloads keep their 512 KiB cap. New receipts store a versioned result digest; legacy raw-state receipts remain fully verified. All async drift, tree, instance-impact, paint, main-link and override checks remain in force; the compact token does not grant permission to skip them or to trim snapshot data.

Apply the same approved request with dryRun=false and expectedState from preview. On SOURCE_CHANGED inspect/repreview. After timeout reuse the SAME operationId with dryRun=true; replay must validate result. Never bypass changed/conflicting/incomplete receipts with another ID. On incomplete rollback report exact changedNodeIds, createdPropertyIds, cleanup errors and cause; never delete existing layers or overwrite concurrent manual edits.

## Explicit recovery of a failed alignment

A read-only recovery preview may be prepared for the SAME operationId and identical original request when the recorded operation is incomplete, the target schema is empty, every previously created property is absent/unbound, slot candidates remain FRAME and no result chunks remain. Other states stay blocked. The preview must include prior cause/completed/remaining/cleanup details, fresh complete instanceImpact and current before/after field values. It does not mark the old attempt successful or clear its receipt.

Present the actual residual state before applying. Reuse existing exact approval when the current before/after changes remain wholly within the previously approved fields and targets, and no outside change is being accepted or repaired. Ask only if recovery would extend that scope or accept unresolved outside changes; do not require approval twice for the same exact work. The preview's requiresApproval flag states the normal finished-master authorization requirement and does not revoke a valid prior approval. A new recovery-prefixed expectedState binds the entire live capture, exact request and prior receipt; an old ordinary apply token cannot resume an incomplete attempt. Preserve prior failures in bounded history when the approved retry begins. Recheck receipt/state drift before writes. New operation IDs, deletion of failure receipts and silent acceptance of unresolved changes are forbidden. A nonempty target schema, already converted slots, lingering old property references/values, receipt chunks, conflicts or unsupported preservation stop this recovery path.

Read back source unchanged, target key/ID, full new property IDs/propertyMap, refs/types, children/order, paint bindings, main identities and affected instance text/states/content. Re-run compatibility using actual propertyMap and inspect PNGs. The user grants visual acceptance. Do not call the entire layout theme conversion complete after schema alignment.
